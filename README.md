# 牛马对账 2.0

`newmore-datachecker` 是上海速创—聚合力账单核对工具“牛马对账”的纯浏览器版本。账单文件在浏览器内读取、汇总和比对，不写入数据库，也不会上传到服务器。

当前 `main` 直接以 Web 2.0 工程为根项目。原 Delphi 1.0 桌面版统一归档在 [`delphi/`](delphi)，正式历史快照见 [`v1.0.0`](https://github.com/wesleygong-hub/newmore-datachecker/tree/v1.0.0)。

## 当前核对规则

- 唯一匹配键：`财务年月 + 业务年月 + 身份证号`。
- 速创和聚合力数据先分别按匹配键汇总，再进行比对。
- 差额方向：`速创汇总金额 - 聚合力汇总金额`。
- 比对四类金额：社保总计、公积金总计、服务费总计、对账总金额。
- 金额统一四舍五入到分；差额必须为 `0.00` 才判定金额一致，无容差。
- 采暖费、重大疾病、工会费、滞纳金等不单独展示，只通过账单总额影响“对账总金额差额”。
- 客户编号不参与匹配。可选客户清单只补充客户组名称和发包方名称。

## 使用方法

1. 选择一份速创账单。
2. 选择一份或多份聚合力账单。
3. 如有需要，展开“添加可选的客户清单”并选择客户清单。
4. 点击“开始核对”。
5. 在页面筛选一致、差异、单边数据或导入错误，最后点击“导出 Excel”。

浏览器会自动查找最符合格式的工作表，并在前 15 行内识别表头。当前版本不提供数据库式模板配置，字段别名集中维护在 `src/lib/excel.ts`，后续格式发生变化时可在这里快速扩展。

### 年度大文件模式

当任一账单达到 15 MB，或两套账单合计达到 30 MB 时，程序会自动进入大文件模式：

- `.xlsx` 文件按压缩数据流逐行读取，不在内存中展开整个工作簿。
- 每读取一行就按三键汇总，金额用整数“分”累计。
- 单文件安全上限为 150 MB，全部账单合计上限为 300 MB。
- 有效明细上限为 100 万行，单侧三键唯一结果上限为 50 万条。
- 大文件模式只导出核对结果、导入错误、统计摘要和客户映射异常，不复制两套原始明细。
- 大文件模式只支持 `.xlsx`；超过阈值的 `.xls` 应先在 Excel 中另存为 `.xlsx`。

2020 年度压力样例包含速创 202,072 条有效明细和聚合力 208,832 条有效明细，浏览器端生成 224,260 条三键结果。

### 主要输入字段

速创账单需要能够识别：

- 财务年月（或账单年月；旧账单可从文件名推断）
- 业务年月（或发生年月）
- 身份证号、姓名
- 社保总额，或原格式中的各社保险种金额
- 公积金总额，或原格式中的基本/补充公积金金额
- 服务费类金额（或管理费）
- 对账金额；旧格式也支持用“总计 - 薪酬金额”计算

聚合力账单需要能够识别：

- 财务年月、业务年月
- 身份证号、雇员姓名
- 各项社保公司/个人金额
- 基本及补充公积金公司/个人金额
- 人事管理、薪酬、资料管理等服务费字段
- 总额

可选客户清单至少需要“客户编号”，并包含“客户组名称”或“发包方名称”之一。可直接使用 [Excel 客户清单模板](docs/客户清单模板.xlsx)，避免 CSV 在 Windows Excel 中出现中文编码问题。

## 导出内容

普通模式导出的工作簿包含：

- `对账结果`：三键汇总后的 16 列核对结果
- `速创原始明细`
- `聚合力原始明细`
- `导入错误`
- `统计摘要`
- `客户映射异常`

大文件模式省略 `速创原始明细` 和 `聚合力原始明细`，避免生成 Excel 时再次产生过高内存占用。

普通模式按旧版结果文件统一设置等线 11 号字体、深灰表头、自动换行、细边框、列宽、筛选和两位小数金额格式。单张表正文超过 25 万个单元格时自动省略逐格边框；年度大文件模式使用高速写入器，优先保证浏览器内存和导出成功率。

## 本地开发与验证

需要 Node.js 20 或更高版本。

```powershell
npm ci
npm run dev
```

浏览器打开终端显示的本地地址，默认是 `http://127.0.0.1:5173/`。

```powershell
npm test
npm run build
```

生产文件会生成在 `dist/`。`npm test` 包含三键汇总、精确到分、单边数据、客户映射和历史 Excel 样例回归。

## 部署到阿里云轻量应用服务器

生产环境由 Nginx 提供静态资源，并通过独立的轻量认证服务保护整个应用。认证服务仅处理用户名、密码摘要和登录会话，不接收 Excel 文件，也不需要数据库或 Node.js 常驻进程。

1. 在本地执行 `npm ci` 和 `npm run build`。
2. 使用 `deploy/generate_user.py` 在安全目录生成用户密码摘要和会话密钥；明文密码不得写入配置或提交 Git。
3. 将 `dist/` 和 `deploy/auth_server.py` 发布到独立版本目录。
4. 参考 [认证服务配置](deploy/newmore-datachecker-auth.service.example)、[环境变量示例](deploy/auth.env.example) 和 [Nginx 配置示例](deploy/nginx.conf.example) 启动认证保护。
5. 检查认证服务健康状态、Nginx 配置与 HTTPS 登录流程后再开放访问。

即使部署到公网服务器，用户选择的 Excel 仍只在当前浏览器内处理；服务器只保存登录账号的加盐密码摘要和短期会话信息，不会接收、保存或处理账单文件。

## 仓库结构

- `src/`：Web 2.0 应用源码。
- `delphi/`：Delphi 1.0 桌面版归档。
- `docs/releases/`：正式版本发布说明。
- `deploy/`：静态资源、认证服务和 Nginx 部署配置示例。

真实账单、核对导出文件、本地依赖和构建产物均不会提交到仓库。
